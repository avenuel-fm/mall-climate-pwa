# 쇼핑몰 공조 관리 앱 (PWA)

실내외 온도·습도를 입력하면 **불쾌지수와 쾌적/주의/불쾌 상태, 공조기 조정 권고**를 보여주고,
최근 5일 그래프·CSV·인쇄용 리포트·구글 시트 저장을 지원하는 모바일 웹앱입니다.
순수 HTML/CSS/JS이며 빌드 과정이 없습니다.

## 파일 구성

| 파일 | 역할 | 수정 필요 |
|---|---|---|
| `config.json` | **매장 이름, 층/구역, 쾌적 범위, 판정 기준, 권고 문구, 구글 시트 주소** | 매장마다 이것만 수정 |
| `index.html`, `style.css`, `app.js`, `usage.js` | 앱 본체 (`usage.js`는 공조기·에어커튼 탭) | 보통 불필요 |
| `sw.js`, `manifest.webmanifest`, `icons/` | 설치(PWA)·오프라인 동작 | 아이콘 교체 정도 |
| `google-sheets/Code.gs` | 구글 시트 저장용 스크립트 (버전 3: 온습도 + 공조기 + 에어커튼, 인증 키 avenuel02 설정됨) | 인증 키만 변경 |
| `usage.js` | 공조기·에어커튼 탭 + 사용시간 리포트 | 보통 불필요 |
| `vendor/` | (선택) 그래프 라이브러리 오프라인 보관 | 아래 참고 |

## 1. 내 PC에서 먼저 보기

파일을 더블클릭하면 일부 기능(설정 파일 읽기, 설치)이 막힙니다. 아래처럼 간이 서버로 여세요.

1. 이 폴더에서 터미널(명령 프롬프트) 열기
2. `python -m http.server 8000` (Python 설치 필요) 실행
3. 브라우저에서 `http://localhost:8000` 접속

## 2. 인터넷에 올리기 (폰에서 쓰려면 필수, 무료)

PWA 설치와 구글 시트 연동은 **https 주소**에서만 동작합니다. 가장 쉬운 방법은 Netlify입니다.

1. https://app.netlify.com/drop 접속 (가입 필요)
2. 이 폴더 전체를 화면에 끌어다 놓기
3. 생성된 주소(예: `https://xxxx.netlify.app`)를 폰 크롬으로 열기
4. 크롬 메뉴(⋮) → **홈 화면에 추가 / 앱 설치**

수정할 때는 같은 방법으로 다시 올리면 됩니다. (GitHub Pages도 가능)
앱은 접속할 때마다 최신 `config.json`을 확인하므로, 설정만 바꿔 올려도 즉시 반영됩니다.

## 공조기 탭

- 하단 **공조기** 탭에서 공조기 38대(6층~1층, B1층, B3층. 예: "6층 39번 공조기", "B1층 1번 공조기-LGF", B3층 "직원식당 공조기"·"직원식당 외조기"(번호 40·41))의 **가동 시작/종료 시각**을 입력합니다. 3·37·38번은 화면·통계에서 빠졌고 예전 기록은 그대로 보관됩니다. `오전/오후 → 시(1~12) → 분(00/10/20/30/40/50)` 드롭다운이며, 기본 시각이 **미리 선택**되어 있어 다른 시간일 때만 바꾸면 됩니다.
  - 기본 시각: 시작 오전 10:00 / 종료 **6층은 매일 오후 9:50**, **B3층(직원식당)은 매일 오전 8:30~오후 6:40**, 나머지 층은 **월~목 오후 7:20, 금~일 오후 8:20** (`config.json`의 `hvac.defaultEnd`, `defaultEndByDay`, 층별 값은 `floorGroups`)
  - 층마다 이름 배경색이 다릅니다(`floorGroups`의 `tone`).
- **폰**: 한 페이지에 한 층씩 보여주고 화면 좌우의 ‹ › 버튼이나 아래 층 버튼(6층, 5층 …)으로 이동합니다.
- **PC(가로 1100px 이상, 예: 1920×1080)**: 전체가 한 화면에 **표**로 표시됩니다. 가로(열)는 1·2·3구역(`config.json`의 `hvac.zoneRows`), 세로(행)는 6층~1층, B1층, B3층입니다. 구역이 정해지지 않은 공조기(현재 B3층 2대)는 그 층 줄에 '구역 미지정' 표시와 함께 펼쳐 놓습니다. PC 카드에서는 저장 상태가 이름 옆에 나오고, 가동시간 줄은 입력 오류가 있을 때만 보입니다. 상단의 **저장** 버튼으로 한 번에 저장합니다.
- 카드의 **미저장 / 저장됨** 표시로 상태를 확인합니다. **저장**을 누르면 ① 직접 바꾼 공조기 ② 화면에 보이는 공조기 중 아직 기록이 없는 것(기본 시각 그대로)이 저장됩니다. 폰에서는 보고 있는 층만 해당합니다.
- 종료가 시작보다 빠르면 오류로 안내합니다. 자정(오전 12:00)을 종료로 고르면 24시로 계산합니다. 시작·종료를 모두 비우면 '입력 없음'(통계 제외)입니다.
- 날짜를 바꿔 지난 기록을 입력/수정할 수 있고 기록은 **기간 제한 없이 계속 보관**됩니다.
- **통계** 화면: 일별 가동시간 합계(막대)와 1대당 평균(선), 공조기별 평균·합계 표, 요약 수치.
- 저장 위치: ① 이 기기 ② 구글 시트('공조기' 시트) ③ CSV / 백업 파일(통계 화면 맨 아래).
- 급기·배기 온도 입력은 삭제되었습니다. (구글 시트의 해당 열은 비어 있고, 스크립트 교체는 필요 없습니다)

## 층·구역, 설정 잠금

- 층은 **6F → 1F → B1F** 순서로 표시되고, 구역은 **1구역·2구역·3구역**입니다. **B1F는 1구역만** 표시됩니다. (`config.json`의 `floors`, `zones`, `floorZones`)
- 예전에 저장한 `A/B/C구역` 기록은 자동으로 `1/2/3구역`으로 바뀌어 표시됩니다. (`legacyZones`)
- **설정 탭**은 들어갈 때마다 비밀번호(4자리) 입력창이 뜨고, 입력 전까지 화면이 흐리게 보이며 조작할 수 없습니다. 다른 탭으로 나가면 다시 잠깁니다. 비밀번호는 코드에 고정되어 있으며 앱 안에서 바꿀 수 없습니다. 화면 잠금용이라 보안 장치는 아닙니다. (구글 시트 인증 키와는 별개)

## 헤더 실외온도

- 화면 맨 위 가운데에 '잠실 에비뉴엘' 좌표의 현재 기온·습도를 표시합니다. 10분마다 갱신하며 오프라인이면 마지막 값(시각 표시)을 보여줍니다.
- 입력 탭의 실외 온도·습도 칸도 이 값으로 자동 채워집니다. (직접 고치면 그 값이 우선)
- 날씨 데이터는 Open-Meteo(기상 모델값)입니다. 기상청 관측값과 1~2°C 차이가 날 수 있고, **Open-Meteo 무료 이용은 비상업 용도 기준**입니다. 사업장 상시 운영에 쓰실 경우 이용약관을 확인하시거나 유료 플랜 또는 기상청 API 연동을 검토하세요.
- 위치는 `config.json`의 `weather.lat / lon`, 끄려면 `weather.enabled: false`.

## 하단 메뉴가 가려질 때 (Netlify 'Powered by' 배지)

배지는 Netlify가 넣는 것이라 앱에서 지울 수 없습니다. 대신 하단 메뉴를 배지 위로 띄웠습니다.
`config.json`의 `ui.tabbarBottomOffset`(px)로 높이를 조절하세요. (배지가 없는 호스팅이면 0)

## Netlify 배포 오류 해결 (`hugo: command not found` 등)

이 앱은 **빌드가 필요 없는 정적 파일**입니다. 오류 로그에 `Custom build command detected: 'hugo'`, `Custom publish path detected: 'public'`이 보이면 **Netlify 사이트 설정에 예전 Hugo 설정이 남아 있는 것**입니다. 아래 중 하나를 하세요.

**방법 1 (가장 확실): 새 사이트로 올리기**
1. https://app.netlify.com/drop 접속
2. 압축을 푼 `mall-climate-pwa` **폴더 자체**를 화면에 끌어다 놓기 (zip 파일이 아니라 폴더)
3. 새 주소가 생기면 그 주소를 사용 (빌드를 하지 않으므로 이 오류가 나지 않습니다)

**방법 2: 기존 사이트 설정 고치기**
1. Netlify → 해당 사이트 → **Site configuration → Build & deploy → Continuous deployment → Build settings → Edit settings**
2. **Build command**를 비우고, **Publish directory**를 `.` 로 바꾸거나 비우기 (현재 `public`이면 반드시 변경)
3. **Environment variables**에 `HUGO_VERSION`이 있으면 삭제
4. 사이트에 Hugo 프로젝트 파일(`hugo.toml`, `config.toml`, `content/`, `themes/` 등)이 남아 있으면 삭제
5. **Deploys → Trigger deploy → Clear cache and deploy site**

**공통 주의**
- 폴더 안의 `netlify.toml`, `index.html`이 **최상위**에 있어야 합니다. (폴더가 한 겹 더 있으면 안 됨)
- `netlify.toml`은 "빌드 없음(echo), 폴더 전체 배포"를 지정합니다. 이 파일이 올라가면 사이트 설정의 hugo보다 우선합니다.
- GitHub 저장소와 연결된 사이트라면 저장소 최상위에 이 폴더의 파일들이 있어야 합니다.

## 3. 다른 쇼핑몰에 적용하기

1. 폴더를 복사
2. `config.json`에서 아래를 수정
   - `siteId` : 매장 고유 ID (영문/숫자, 매장마다 다르게)
   - `siteName` : 화면·리포트에 표시되는 이름
   - `floors`, `zones` : 층·구역 이름 (개수 자유)
   - `ranges` : 쾌적 온도·습도 범위
   - `levels` : 불쾌지수 단계별 기준(maxDI), 이름, 색, 권고 문구
   - `outdoorDiff` : 실내외 온도·습도 차이 경고 기준
   - `advice` : 각 상황별 권고 문구
3. 새로 업로드

> **주의: JSON 문법** — 따옴표(`"`)·쉼표(`,`)를 지우지 마세요. 마지막 항목 뒤에는 쉼표를 붙이지 않습니다. 저장 후 https://jsonlint.com 에 붙여넣으면 오류 위치를 알려줍니다.

### 판정 기준(기본값)에 대해

`levels`의 기본값(쾌적 74 미만, 주의 78 미만, 불쾌 78 이상)은 **쇼핑몰 실내 운영용 시작값**입니다.
기상청 공식 불쾌지수 단계(68/75/80)는 옥외 기준이라 실내 냉방 환경에 그대로 쓰면 대부분 '주의'가 나옵니다.
현장에서 고객 반응·민원과 비교해 값을 조정하세요. 변경하면 이전 기록의 상태 표시도 새 기준으로 다시 계산됩니다.

## 4. 구글 시트 연결 (선택)

앱만 써도 기록은 폰(localStorage)에 저장됩니다. 구글 시트를 연결하면 여러 직원·여러 기기의 기록을 한곳에 모으고 백업할 수 있습니다.

1. 구글 시트를 새로 만들기 → 메뉴 **확장 프로그램 → Apps Script**
2. 기본 코드를 지우고 `google-sheets/Code.gs` 내용을 붙여넣기
3. 맨 위 `TOKEN` 값을 본인만 아는 문자열로 바꾸기 (예: `mall-2026-xk93`)
4. 저장 후 **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
5. 권한 승인 후 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`) 복사
6. 앱의 **설정 탭**에 URL과 같은 TOKEN을 입력 → **지금 동기화**
   - 매장 전체에 쓰려면 `config.json`의 `sheets.url`, `sheets.token`에 넣어 두면 직원이 입력할 필요가 없습니다.
7. Apps Script 코드를 고쳤다면 **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포**를 해야 반영됩니다. (웹앱 주소는 그대로 유지됩니다)
8. **공조기·에어커튼 기능을 쓰려면 Code.gs를 이번 버전(버전 3)으로 교체한 뒤 7번처럼 다시 배포해야 합니다.** 예전 스크립트가 남아 있으면 앱이 "스크립트가 예전 버전입니다"라고 알려 주고, 시트에는 아무것도 쓰지 않습니다.
   - 시트에는 `기록`(온습도), `공조기`, `에어커튼`(일일 가동시간) 탭이 자동으로 만들어집니다.

동작 방식
- 저장 즉시 시트로 전송하며, 오프라인이면 기기에 쌓아 두었다가 연결되면 전송합니다. (상단 배지에 미전송 건수 표시)
- 같은 기록은 중복 저장되지 않습니다.
- 동기화할 때 다른 기기에서 입력한 최근 기록도 가져와 그래프에 합칩니다.
- 앱에서 기록을 삭제해도 시트 기록은 남습니다. 시트에서 직접 지우세요.
- 보안: 웹앱 주소와 TOKEN을 아는 사람만 읽고 쓸 수 있습니다. 주소와 키를 외부에 공개하지 마세요. `config.json`에 키를 넣으면 사이트 주소를 아는 누구나 파일을 볼 수 있으니, 직원 전용 주소로만 쓰거나 설정 탭에서 기기별로 입력하세요.

## 5. 그래프 라이브러리(Chart.js)

그래프는 Chart.js로 그립니다. 앱이 처음 열릴 때 인터넷(cdnjs)에서 한 번 받아 기기에 저장하므로 이후에는 오프라인에서도 동작합니다.
매장 와이파이가 외부 접속을 막는다면:

1. https://cdnjs.cloudflare.com/ajax/libs/Chart.js/4.4.1/chart.umd.min.js 를 열어 **다른 이름으로 저장**
2. 파일 이름을 `chart.umd.js`로 바꿔 `vendor/` 폴더에 넣고 업로드

앱은 `vendor/chart.umd.js`를 먼저 찾고, 없으면 인터넷에서 받습니다.

## 6. 공조기·에어커튼 탭과 사용시간 리포트

- `config.json`의 `hvac`(38대: 층별 `floorGroups`, PC 구역 열 `zoneRows`), `curtain`(36대: 그룹별 대수는 `groups`)에서 대수, 한 화면 개수(`perPage`), 분 단위(`minuteStep`, 기본 10), 기본 시각을 바꿀 수 있습니다.
- **입력**: 날짜를 고르고(최근 31일 이내) 가동 시작·종료 시각(오전/오후 · 시 · 분)을 입력한 뒤 **[저장]**. **가동하지 않았으면 `미가동`을 체크**하면 0시간으로 통계에 반영됩니다. 입력이 없는 칸은 통계에서 제외됩니다.
- **리포트 탭 → 공조기 / 에어커튼**: 요약(오늘 **미입력 대수**, 오늘 합계, 1대 1일 평균, 기간 합계 · 30/90일/1년/전체 선택), **오늘 제외 최근 3일 비교**(전날보다 길면 빨강 ▲, 짧으면 파랑 ▼), 대수별 표, 추이 그래프(기간이 길면 월별), 일일 기록.
- **저장 방식**: 이 기기(IndexedDB)와 구글 시트에 **기간 제한 없이** 계속 쌓입니다. 새 기기에서는 리포트 탭의 [시트에서 전체 기간 불러오기]를 한 번 누르세요. CSV(전체 기간)와 백업 파일도 지원합니다.
- 예전 공조기 기록은 자동으로 옮겨지며, 구글 시트의 기존 '공조기' 시트는 그대로 이어서 사용합니다.

## 7. 헤더 실외 온도

- 화면 상단에 에비뉴엘 좌표(`config.json`의 `weather.lat/lon`) 기준 현재 기온·습도를 표시하고 10분마다 갱신합니다. 누르면 입력 탭의 실외값이 현재 날씨로 채워집니다.
- 데이터 출처는 Open-Meteo(기상 모델값)이며 기상청 관측값과 1~2°C 차이가 날 수 있습니다. Open-Meteo 무료 API는 비상업 용도 기준이므로, 정식 운영에서 상업적 이용에 해당하면 유료 플랜이나 기상청 API로 교체를 검토하세요.
- 인터넷이 끊기면 마지막 값을 시각과 함께 표시합니다. 끄려면 `weather.enabled`를 `false`로 바꾸세요.

## 8. 하단 메뉴가 "Powered by Netlify" 배지에 가릴 때

- 배지는 Netlify가 붙이는 것이라 앱에서 지울 수 없습니다. 대신 `config.json`의 `ui.tabbarBottomOffset`(Netlify라면 56px, GitHub Pages는 0)만큼 하단 메뉴를 위로 띄워 배지에 가려지지 않게 했습니다. 배지가 없는 곳에 올리면 `0`으로 바꾸세요.

## 계산식

불쾌지수 DI = 0.81×T + 0.01×H×(0.99×T − 14.3) + 46.3 (T: 온도 °C, H: 상대습도 %)

## 사용 팁

- **순회 점검**: 입력 탭의 '저장 후 다음 구역으로 자동 이동'을 켜 두면 1F A → B → C → 2F A … 순서로 위치가 넘어갑니다.
- 실외 온습도는 한 번 입력하면 2시간 동안 자동으로 채워집니다. 바뀌었으면 고쳐서 저장하세요.
- 앱 업데이트가 안 보이면 앱을 완전히 닫았다가 다시 여세요. (파일 구성이 바뀌었을 때는 `sw.js`의 `CACHE` 숫자를 올려야 확실히 갱신됩니다)
